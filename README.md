# natural-japanese-writing

AIが書いたように読める日本語を、事実を変えずに自然な日本語へ直す Claude Code / Codex / Cursor 向けスキル。

英語圏の同種スキル（humanizer、avoid-ai-writing）は「delve」「tapestry」「em dash」など英語の癖が対象で、日本語には効かない。このスキルは日本語の癖を、国内の実測と研究を根拠に扱う。

## 何が違うか

- 文書の種類を先に決める。業務文書（報告・提案書・議事録・Slack）では体験談や感情を足さない。読み物（ブログ・note）では残す。
- 6層で点検する。表記・語彙・文末とリズム・構文・構成・中身。癖は全50項目。
- 癖の強さで扱いを変える。★は1つで直す。それ以外は同じ段落に3つ重なったら直す。人の文章のしるしだった表現（「最後に」「まさに」）は直さない。
- 根拠を自分で測っている。人40本・AI 40本の評価セットで指標ごとの分離度（AUC）を出し、しきい値を決めている。人のほうが多く使う表現（「に関して」「〜することができます」）は癖の一覧から外した。
- 数える道具がある。`scripts/check.py` が、太字・全角ダッシュ・行末だけ落ちた句点・「〜ではなく」・頻出語・語尾の連続・文の長さのばらつきを数える。
- 日本語固有の癖を持つ。句点の行末落ち、読点の打ちすぎ、コロン後の半角スペース、「」の入れ子、体言止めゼロ、直しすぎの常体混入。
- 実務の癖も持つ。技術事象の擬人化（「台帳が壊れた」）、内部識別子が主語の説明（「plan_config の価格」）、非エンジニア宛の報告に書かれたファイルパス、A案・B案と経緯に頼った資料。

## 導入

```
git clone https://github.com/kojikojikojikoji/natural-japanese-writing ~/.claude/skills/natural-japanese-writing
```

Codex は `~/.codex/skills/`、Cursor はルールとして `SKILL.md` を読み込ませる。

## 使い方

「AIっぽさを消して」「自然な日本語にして」「人が書いたように直して」と頼む。ファイル名を渡せば、地の文だけを直して上書きする。

数えるだけなら:

```
python3 scripts/check.py 文章.md
pbpaste | python3 scripts/check.py
```

## 構成

| ファイル | 内容 |
|---|---|
| `SKILL.md` | 手順と6層の点検表 |
| `scripts/check.py` | 機械チェック（Python 3.9 以上、依存なし） |
| `examples/` | 書き直し前後の例 |
| `eval/` | 評価セット（AI 40本を同梱、人の側は非公開）と計測スクリプト。しきい値の根拠は `eval/README.md` |
| `tests/` | 回帰テスト。`python3 tests/test_examples.py` |

## 根拠

SKILL.md 末尾の「参考にしたもの」に、実測記事・研究・先行スキルを挙げている。先行スキルからは考え方だけを参考にし、文面とコードは流用していない。
